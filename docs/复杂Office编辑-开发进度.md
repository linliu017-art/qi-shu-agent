# 阶段3-7：页面内复杂Office编辑与原文件版本

2026-10-31 用户要求第二期必须支持复杂Office无损编辑，并明确选择“在启枢页面中直接编辑”。此决策扩展阶段2-2/3-2中仅支持简单结构编辑的原边界：新增Word/Excel/PPT复杂内容编辑与保真验证，不得以旧功能替代。沿用用户授权先写文档后直接开发。前端手册及AGENTS底线已对账，无冲突。

## 能力地图与顺序

| 模块 | 目的与依赖 |
| --- | --- |
| native-office-storage | 先原样保存docx/xlsx/pptx文件字节及各个版本，允许仅图片但合法的Office进入编辑存储；旧文件/版本不可覆盖，源文件与结果关联可追溯。复杂文件安全校验仍阻止宏、加密、外链和压缩炸弹。 |
| embedded-office-editor | 对接本地可控网页Office编辑引擎，用户在启枢内部编辑图片、表格、图表、公式、幻灯片等；依赖native-office-storage与服务部署。引擎不可用时明确报错，不回退到会丢复杂内容的简化编辑。 |
| office-save-safety | 编辑会话按成果版本创建；签名与回调校验，限定来源地址、防止SSRF/开放文件读取、超时及幂等；保存为新版本，旧版本可恢复，冲突明确提示，图片、图表、公式、动画与版式保存前后需验证。 |
| real-file-acceptance | 虚构且含图片、页眉页脚、表格、图表、合并单元格、公式、PPT母版、动画、备注等实际文件，用真实浏览器和实际Office编辑器打开、修改、保存、重新打开并对比；逐项列出支持与缺陷，不用模拟编辑器冒充成功。 |

## 技术约束与边界

- 无损指用户未修改的功能内容、结构和呈现需在支持的真实样例中保存；OOXML包的每一字节一致不作为必然条件。所有格式、特性与不同编辑器未完成实测之前，不承诺通用100%无损；不能让不支持的特性静默损坏。原始版本字节应完整保留，可恢复。
- 候选ONLYOFFICE Docs网页编辑器通过本机隔离虚拟机测试，用户资料未发往外部。当前测试服务位于临时目录，还不是可持续启动方案；其社区版有AGPL与品牌要求，正式发布适用条款需单独核对。官方文档：https://api.onlyoffice.com/docs/docs-api/get-started/how-it-works 和 https://helpcenter.onlyoffice.com/docs/installation/docs-community-install-docker.aspx 。
- 初始实现是可独立测试的本地原文件版本存储基础，不开放未完成的编辑入口、不停止旧功能、不改用户现有文件，且不能把结构化重导出结果当原样保存。新增SQLite表与单事务版本保护；原文件由用户明确选择，不处理用户未授权目录。
- 类型白名单docx/xlsx/pptx，真实文件结构、体积、路径和宏/外链校验不低于现有上传；不要要求Office必须有可提取文字（图像型文件也可编辑），但不能宣称识别了图片文字。发生任何校验错误必须拒绝且不创建版本。
- 前端仅当服务可实际使用并经过验收后才显示新编辑入口，保存状态与失败明确，不把回调伪装成完成。服务地址与密钥只在服务端配置，真实用户资料不得发往公共演示或未经明确授权的外部服务。
- 新能力必须有后端自动测试、重启恢复和多版本并发冲突测试；真实编辑器及本机/移动端检查、复杂样例验收通过前，第二期仍为未完成。

## 2026-11-01 真实编辑器联调

- 本地独立测试服务已接入原文件导入、签名下载、编辑后回调、版本保存、并发冲突和异常结果保留。入口仍默认关闭，现有生产预览未启用。
- 隔离测试：PPT新增页面后，原图片和演讲者备注保留；Word新增文字后重新打开，图片与页眉可见；Excel修改数值后，公式、图表和合并单元格可重读。编辑器保存Excel省略可选尺寸字段导致首次回写失败，已修复并加入回归测试；原稿未被覆盖。
- 编辑器与服务端时钟有轻微偏差时会拒绝合法签名，已限制在5秒内允许偏差，仍校验签名和到期时间。编辑器接管DOM引起页面报错的问题已修复。
- 原文件PPT已在隔离环境接入实际幻灯片只读预览，验证了预览、进入编辑及无改动退出返回预览；入口仍仅在测试服务启用时显示。
- 尚缺：真实复杂样例中的母版、动画、嵌入对象、更多图表与版式跨软件检查；没有可保证所有Office特性无损的完整检测；手机宽度可用性、本机服务可靠启动与恢复、正式发布许可核对。部分检测发现风险后仅保留候选并提示用户检查，不能推断未提示即无损。第二期不能宣布完成。
